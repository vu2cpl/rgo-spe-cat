# RGO ONE → SPE CAT Server — Handover

Nov 13, 2026

## Purpose and scope

An ESP32-S3 sits between the RGO ONE and the SPE amplifier. It is the only device that talks to the radio's CAT port, and it passes frequency and mode to the amp so the SPE follows band changes automatically.

- **In scope:** CAT polling of the RGO ONE over USB, Kenwood-format frequency output to the SPE over TTL serial, and Wi-Fi TCP CAT for PC software (Hamlib / WSJT-X).
- **Optional:** MQTT publishing of frequency, band and TX state to the shack's Node-RED.
- **Out of scope:** TCI, audio, IQ and panadapter. Any IF-out panadapter work is a separate SDR box, not this ESP32.

## Decisions

CAT only, on an ESP32-S3 N16R8, connected to the radio over USB and to the SPE over direct TTL.

| Topic | Decision | Reason |
| --- | --- | --- |
| Radio connection | USB host from the ESP32-S3 to the RGO ONE's USB Type B socket | The radio exposes CAT on USB only; this avoids opening the radio |
| Internal TTL tap | Not used | Needs the radio opened and handling of contention with the internal USB-serial chip |
| Board | ESP32-S3 N16R8 | Has USB OTG host; flash and PSRAM leave room for OTA |
| SPE connection | Direct TTL from an ESP32 UART, no MAX3232 | The SPE accepts TTL-level CAT |
| Protocol to SPE | Kenwood emulation (`FA;`, `IF;`) | Common format the SPE understands |
| TCI | Dropped | No IQ or audio from the RGO ONE, and the SPE and WSJT-X don't use it |
| Bluetooth serial | Dropped | The S3 has BLE only, so no SPP COM port; macOS SPP is unreliable anyway |
| Audio over network | Dropped | Would need I2S ADC/DAC and Wi-Fi buffering; out of scope |

## Hardware and wiring

The build is an ESP32-S3 N16R8 board, a USB cable to the radio, and three wires to the amp.

| Link | From | To | Notes |
| --- | --- | --- | --- |
| USB CAT | S3 USB OTG port (host) | RGO ONE USB Type B | USB-C to USB-B cable. OTG port must supply 5 V on VBUS: set the board's jumper/solder pad or feed 5 V in |
| SPE TX data | S3 UART TX (3.3 V) | SPE CAT input | Usually reads fine at 3.3 V; add a 74AHCT125 buffer if the amp misses characters |
| SPE RX data | SPE CAT output | S3 UART RX | Only if the amp polls. Measure first: 5 V needs a divider, RS-232 ±12 V needs a proper level shifter. Leave unconnected if the amp only listens |
| Ground | S3 GND | SPE ground | Required |

RF hardening: shielded enclosure, ferrites on the USB, CAT and power leads. The radio runs 100 W with the SPE close by.

## Firmware design

One core owns the radio and holds its state; every output reads from that state.

1. **Radio link:** USB host with the CDC/VCP driver matching the RGO ONE's USB-serial chip. Polls `FA;`/`IF;` every 100–200 ms. Radio command set believed to be Kenwood TS-480 style; confirm against the RGO ONE manual.
2. **Rig state:** frequency, mode, TX/RX, timestamp of last good reply.
3. **SPE output:** Kenwood emulation on a UART. Answers `IF;`/`FA;` queries and also pushes unsolicited `FA…;` on change, so it works whether the amp polls or listens.
4. **TCP CAT server:** Kenwood over TCP for Hamlib / WSJT-X. All writes to the radio are queued through the core so PC software can't stall polling.
5. **MQTT (optional):** publish frequency, band, TX state to Node-RED.
6. **Fail-safe:** if the radio stops answering, stop sending frequency to the SPE rather than hold a stale band.
7. **Housekeeping:** OTA updates, Wi-Fi config, a status page.
